# Supabase Authの採用

## 背景
本アプリでは、ユーザーごとにホテルの記録を管理できるようにしたいと考えた。
具体的には、ユーザーごとにデータを分け、他のユーザーによる閲覧・編集・削除を防ぐことを目的としている。
また、将来的には複数の端末から同じデータにアクセスできるようにし、実際のWebサービスに近い機能を実装したいと考えた。
これらを実現するため、ユーザーを識別するログイン機能が必要になった。


## 検討した選択肢

### 1. 自分でログイン機能を作る
- メリット：ログインの仕組みを詳しく学べる。
- デメリット：開発に時間がかかり、セキュリティ対策も難しい。

### 2. Firebase Authentication
- メリット：ログイン機能が用意されており、比較的簡単に実装できる。
- デメリット：Firebase独自の仕組みを覚える必要がある。

### 3. Supabase Auth
- メリット：ログイン機能が用意されており、将来的にデータベースとも連携しやすい。
- デメリット：Supabaseの使い方を覚える必要がある。


## 決定
認証機能にはSupabase Authを採用する。


## 採用理由
- ログイン機能を一から作るよりも、ホテルレビューサイト自体の開発に時間を使いたかったため。
- 将来的にホテル情報をデータベースに保存する予定があり、Supabaseならログイン機能とデータベースを連携させやすいため。
- 無料プランがあり、個人開発でも利用しやすいため。


## デメリット・注意点
- 無料プランには利用制限がある。
- Supabaseに依存するため、将来ほかのサービスに変更する場合は修正が必要になる。


## 今後の課題
- ホテル情報をlocalStorageからSupabaseのデータベースに移す。
- ログインしたユーザーが、自分のホテル情報だけを閲覧・編集・削除できるようにする。
